# SpecPrune 中期展示实验

本轮使用当前工具箱的 SpecPrune 封装，对 OpenVLA-OFT LIBERO-Object 做配对闭环。2026-11-11 已完成 50 对、100 回合，全部原始报告与 episode 文件通过独立复核。[汇总及逐任务结果](server-evidence/2026-11-11/specprune-object/report.json)

## 可展示的结果

| 指标 | 原生基线 | SpecPrune |
|---|---:|---:|
| 任务成功 | 49/50（98%） | 49/50（98%） |
| 平均查询策略耗时 | 275.47 ms | 210.03 ms（降低 23.75%） |
| 平均每回合策略总耗时 | 4900.44 ms | 4301.93 ms（降低 12.21%，1.139×） |
| 模型查询次数 | 887 | 1020 |
| 环境动作数 | 6933 | 7026 |

两者均成功的 48 对中，策略总耗时比值为 1.134×。SpecPrune 在任务 2 / 状态 7 失败，基线在任务 5 / 状态 5 失败，其他配对均成功。相同的总成功率不代表每个任务行为相同。

成功率差的配对 bootstrap 95% 区间为 −6 至 +6 个百分点；回合策略耗时加速比区间为 0.983–1.298，包含 1。因此可以展示本轮观测到的平均收益，尚不能宣称稳定保证加速或成功率不下降。初始状态、seed 与共享硬件范围见下文。

中期汇报可这样讲：**“我们将 SpecPrune 接入统一评估链，在 10 个 Object 任务、50 对初始状态上完成真实闭环。基线与加速均成功 49 次，平均查询耗时降低 23.75%，每回合策略耗时降低 12.21%。工具箱不仅检查模型能否运行，还记录调用次数、失败回合和恢复情况，并根据设定的质量门槛进行选择。”**

## 固定协议

- Object 任务 0–9，每个任务初始状态 5–9，seed=7，共 50 对、100 回合。
- 基线与 SpecPrune 使用同一检查点、BF16、eager attention；每对使用相同初始状态，按任务与初始状态索引交替运行顺序。
- SpecPrune 启用 token_prune、dynamic_prune、action_adapter，保持现有 Object 配置，不根据本轮结果调参。
- 每对先检查保留全部 token 对照、实际剪枝、参数与模块恢复，再跑闭环。失败任务保留；执行错误不算有效回合。
- 前 9 次不执行环境动作的控制器调用仍计入策略总耗时。预热在固定输入阶段完成，闭环不事后剔除慢调用。
- 两批分别覆盖任务 0–4 与 5–9，使用 H20 GPU 1、3。各对基线与加速均在同一 GPU；共享服务器上的计时不能视为独占硬件基准。

## 看哪些数字

| 指标 | 含义 |
|---|---|
| 成功回合 / 总回合 | 完整任务结果，不能用固定输入动作误差代替 |
| 模型调用次数 | `queried=true` 的真实动作块查询，不包含单纯从队列取动作 |
| 平均查询策略耗时 | 查询调用的同步墙钟耗时，包括图像准备、模型和控制器处理 |
| 平均每回合策略耗时 | 一回合全部策略调用之和，包括队列与不执行环境动作的调用；不包含仿真 step |
| 环境动作数 | 实际送入环境的动作次数，与策略调用数分开 |

单次查询加速不保证整个回合更快：重规划或轨迹变化可能增加模型调用次数。展示时同时报告成功率、查询耗时和回合总策略耗时。

## 复算与展示

服务器本轮独立目录：`/home/wxy/Rui_work/specprune-display-20261111`。`part-a`、`part-b` 保存各 25 对记录，`smoke` 是预检，与正式任务 0 / 初始状态 5 重复，不叠加样本数。

完整下载两个批次后，在工具箱根目录运行：

```bash
python -B scripts/summarize_specprune.py /实际路径/part-a/report.json /实际路径/part-b/report.json --output /新路径/summary.json
```

脚本重新审核每份报告及 episode 文件，拒绝重复配对、缺失记录、协议混用、模型调用计数不一致或恢复失败。报告包含逐任务成功数和配对初始状态 bootstrap 区间；单 seed 区间不覆盖其他任务分布、其他 seed 或硬件波动。所有样本都成功时，经验 bootstrap 的差值区间可能退化为零，不能解释为保证零风险。

仓库的 `docs/server-evidence/2026-11-11/specprune-object/raw-batches.zip` 包含两批完整原始记录、预检、环境、执行命令及执行源码快照。解压到新目录后可执行上述复算。预检不额外计入 50 对。检查点 46 个文件的校验值另见 `checkpoint-sha256.json`。

无需 GPU 的选择器演示，在工具箱根目录运行：

```bash
python -B -m core select --report docs/server-evidence/2026-11-11/specprune-object/report.json --min-success-pct 90 --max-drop-pp 0 --min-pairs 50 --output runs/specprune-selection-demo
```

预期 `selected=specprune`。90%、允许下降 0 个百分点是演示用的观测样本门槛，不能解释为统计上证明零下降。当前 SpecPrune 选择器以闭环成功率筛查质量，再按固定相同输入的配对动作块计时排序：本轮该计时均值为 212.43 → 179.74 ms（1.182×）。这与上表闭环查询耗时、回合策略耗时属于三个不同统计口径，不能互换。该演示只比较本轮原生与 SpecPrune。

展示顺序：展示模型与环境配置 → 展示一对真实 episode 与调用计数 → 展示完整批次成功数与时间 → 说明本轮适用范围。当前入口为实验评估，不将 `execution_complete` 讲成部署验收通过，也不与不同后端的 FastV/VLA-Pruner 时间直接排总榜。
