# 三个真实初始输入的接入验证

2026-11-02，Codex 通过已授权的 SSH 连接在 H20 服务器直接运行。现有 task 0 基础上增加 LIBERO-Object task 1、2，各使用初始状态 0，seed 7。相同 OFT checkpoint，VLA-Pruner semantic_action，剪除比例 0.5。每个输入 6 对交替调用，共 18 对。

三组均通过 INTEGRATION_PASS：关闭剪枝相对原生动作最大差为 0，卸载后相对原生最大差为 0；视觉 token 512→256，实际下游序列分别 596→340、598→342、598→342。三组动作块的原始夹爪符号均一致。模型对象与 forward 身份恢复、参数采样保持、checkpoint 小文件哈希和大小检查通过。

这不是 18 次任务成功率试验：每项只有一个初始 observation，同一输入重复预热与计时，未执行策略闭环。动作误差尚无用户约定的接受门槛，不能写“准确率无损”。GPU 非独占，SDPA/eager 实际回退路径尚未逐调用审计；表中速度只是描述性结果，不是正式加速承诺。

原始输入 NPZ、完整动作 JSONL、恢复动作 NPZ、环境/源码记录和日志随包保留。任务 0 位于 `server-evidence/2026-11-02/verified-pruner-pair/`，任务 1、2 位于 `server-evidence/2026-11-02/multitask-smoke/`。页面构建器校验 observation 哈希、JSONL 与 report 一致性，并从原始记录重算延迟中位数。

可展示结论：工具箱已能在这一明确配置上完成真实 VLA 模型的可恢复加速接入，并提供可追溯的初步性能与动作变化记录。后续需多初始状态、独立用户复现和闭环质量验收。
