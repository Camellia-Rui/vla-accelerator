# 一次指令，运行与评估一起完成

资源就绪且 project.json 指向正确模型环境后，在工具箱根目录执行：

```bash
python -B -m core select --project project.json --output runs/new-evaluation
```

无需再发第二条“评估结果”指令。未给质量门槛时，自动运行并报告实测数据，保留未定结论；不替用户设定验收标准。要按样本门槛筛选，可在同一命令加上 `--min-success-pct 90 --max-drop-pp 0 --min-pairs 50`。这三个参数须一起提供，数字仅是示例；实际运行的任务和状态数须与要求匹配。详见 [方法选择](METHOD_SELECTION.md)。

## 运行期间的作用

| 路线 | 检查时机 | 核心检查 |
|---|---|---|
| OFT Object | 每个回合完成后 | 完整记录、状态配对、动作、耗时；结束后检查恢复 |
| LightVLA Spatial | 每个回合完成后 | 同上；保留专用训练权重的适用边界 |
| FastV OpenVLA / OFT | 每个回合完成后 | 状态哈希、动作查询、回合耗时；两模式合并审核 |
| SpecPrune Object | 子任务逐回合，批量入口逐对 | 区分实际模型查询与动作队列调用，核对查询计数与配对证据 |

检查发现无效记录会报错停止，不把异常回合当成功，也不在运行途中修改成功率门槛。正常的任务失败仍保留为有效失败样本。当前不实现根据实时成功率自动提前宣布 PASS，也不自动训练或修改剪枝参数。

## 自动交付

- `assessment.json`：执行状态与运行进度；完成后含质量门槛状态、候选与计时汇总。
- `assessment.md`：中文结果，包含成功数、平均模型查询耗时、每回合策略总耗时和墙钟耗时。
- `selection.json`：本次样本满足门槛的候选选择、原始报告路径与 SHA256。
- `measurement/`：原始记录及后端报告。SpecPrune 的每对详细检查保存在对应子目录。

`AUDITED` 只表示运行证据检查完成；`FINISHED` 表示流程结束；`SATISFIED` 只表示观测样本符合指定门槛。它们均不等价于统计上证明成功率不下降或部署验收 PASS。缺少门槛显示 `NOT_SPECIFIED`，证据不足保留 `INCONCLUSIVE`。

## 计时口径

统一报告保留各后端的实际计时边界，不把异构后端直接排名。OFT/LightVLA 查询包含其调用包装；SpecPrune 策略总耗时含队列调用，选择器仍使用同输入配对测试的动作块耗时。FastV 选择器沿用剔除开头五次查询的口径，描述表保留全部已记录查询，因此两处均值可能不同。

FastV 原始 OpenVLA 回合墙钟从首次策略查询至最后一次仿真步结束，不包含开头静置和视频保存；OFT FastV 包围其原生 run_episode 调用，可能包含该函数内部静置。只能在相同后端、相同口径下比较。旧报告缺少回合墙钟时显示缺少记录，不补造数值。
